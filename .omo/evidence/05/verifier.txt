## Defects (blocking)
D1. `resume` is not restricted to paused tasks. routes/tasks.ts maps resume -> to:'in_progress' and transitionTask only checks TASK_TRANSITIONS, where assigned->in_progress is legal (runtime transition). Result: an operator can start an assigned task over REST with no run, bypassing the runtime (verified live: 200). decisions.md claims "Only in_progress can pause so resume always targets in_progress" but never constrains the source state. Same class: pause/cancel are fine (their targets are legal only from human-acceptable states). Fix: resume must require current.status === 'paused' (e.g. pass expected `from` into transitionTask / action->allowed-from map), else 409; add route test `[assigned,'resume'] -> 409, no event`.
D2. Declared input bounds for capabilityTags (<=32 tags, <=64 chars each) are untested: mutants N14 and N16 survive. Behaviour is correct live, but the acceptance-relevant bound has no regression guard. Fix: add 400 cases for 33 tags and a 65-char tag (and 201 at 32/64) to routes/directives.test.ts.
D3. Run timestamp semantics untested: N3 (endedAt only on succeeded) and N12 (startedAt on any transition) survive. Existing test only asserts startedAt/endedAt exist after succeeded. Fix: in services/runs.test.ts assert no startedAt while queued/composing, startedAt set at executing and unchanged afterwards, and endedAt set on failed and escalated.
