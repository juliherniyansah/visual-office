Redhunter HQ — AI Rules & Guide

"Where Humans and AI Work Together" — Interactive 3D AI Virtual Office. Dokumen sumber kebenaran untuk semua AI agent & 3D skill.

Status: Brainstorming — belum ada implementasi
Untuk AI agent: baca dokumen ini SEBELUM task 3D, Blender, aset, karakter, atau task-integration apapun. Skill 3D general = HOW (cara teknis). Dokumen ini = WHAT (apa yang dibangun, style, aturan proyek). Konflik dengan skill → dokumen ini menang. Konflik dengan pesan user terbaru → user menang, lalu update dokumen ini.

1. Hard Rules

MUST

  1. Baca §2 dulu; jika gate belum dibuka user → hanya riset/dokumentasi, tanpa implementasi.
  2. Ikuti style §4 untuk semua aset (gedung, interior, props, karakter).
  3. Pakai naming §6 untuk setiap objek Blender yang akan diekspor.
  4. Simpan scene sebagai hq_vNN.blend tiap iterasi (scene hilang saat Blender restart).
  5. Jadikan apps/assets/blender/build_hq.py sumber kebenaran scene (rebuildable: blender -b -P build_hq.py).
  6. Verifikasi visual dengan render Eevee ke file PNG lalu baca file — bukan klaim.
  7. Simpan API key (Meshy/Sloyd/Trello) hanya di .env lokal yang di-gitignore.
  8. Jaga business logic di backend (Express/MongoDB); objek 3D hanya visual + trigger UI.
  9. Update §11 Changelog bila user mengubah preferensi.

MUST NOT

  1. Blockout Floor 1, clone Nexus HQ/Huddly, atau ubah kode tanpa persetujuan eksplisit user di pesan saat itu.
  2. Bangun 4 lantai detail sekaligus — Floor 1 dulu, evaluasi, baru perluas.
  3. Generate gedung/ruangan utuh sebagai satu mesh via Meshy/Sloyd (monolitik, tidak bisa floor-switch/collision per dinding). Yang boleh: potongan kit modular yang dijahit bpy (§3 Kit Meshy).
  4. Pakai smooth shading, tekstur blur, atau bentuk "meleleh" (lihat §4).
  5. Expose socket Blender MCP (127.0.0.1:9876) ke Tailscale/jaringan — execute_blender_code = Python arbitrer.
  6. Membuat endpoint backend fiktif, status agent palsu, atau mock task permanen di scene.
  7. Mengubah apps/web/src/components/office/ di luar plan MVP aktif (MVP-1 memecah OfficeCanvas.tsx ke folder ini; edit lanjutan mengikuti plan MVP).
  8. Berlangganan/menyarankan bayar tool sebelum uji free tier (§3).
  9. Menyalin desain/branding/aset berhak cipta dari referensi (bruno-simon.com, Fab, Samantrix).

4. Style Spec (terukur)

Kutipan user: "walau poly, saya mau poly yang bagus, realistis gk buram".

PropertiNilai wajib
GayaLow-poly flat-shaded, playful, gamified, clean & tajam
ShadingFlat. Smooth hanya jika user minta eksplisit
MaterialVertex colors / palet flat, 1 shared material per kit bila bisa
Tekstur bitmapHindari; jika ada (hasil Meshy) wajib tajam di kamera dekat
AksenMerah Redhunter terkendali: signage, core tangga, detail kecil
SkalaMeter real-world, origin di ground (y=0)
Grid modularDinding segmen 1 m, tinggi lantai 3.2 m, kolom grid 4 m, props snap 0.8–1 m
Batas bawah kualitasSetara output Meshy
RealismeBoleh sedikit (proporsi, lighting) selama tetap stylized
Konsistensi interior (MUST): interior ikut style yang sama dengan exterior. Variasi dicapai lewat bentuk, prop, dan palet, bukan tekstur:
  • Palet interior boleh lebih hangat (krem/abu terang) dari exterior; aksen merah tetap terkendali
  • Zona warna per fungsi (kerja, meeting, lounge, AI Core) — style sama, aksen beda
  • Kekayaan visual dari siluet prop (rak, tanaman, lampu, whiteboard, sofa), tetap flat-shaded
  • Aset Meshy/Sloyd untuk interior wajib lolos checklist di bawah; gagal → regenerate atau ganti bpy

Tolak (anti-pattern visual): campuran objek realistis/PBR-bertekstur dengan objek low-poly dalam satu scene, bentuk meleleh/blobby, siku tidak 90° tanpa alasan, skala antar-aset tidak konsisten, warna acak di luar palet, neon berlebihan, dekorasi acak, bangunan kotak generik tanpa siluet.

Checklist QA render (jalankan tiap iterasi):

  • Siluet terbaca dari kamera isometrik dan eye-level
  • Tidak ada permukaan blur/noise
  • Aksen merah tidak dominan
  • Skala manusia 1.7 m masuk akal terhadap pintu/desk
  • Naming §6 lengkap

5.2 Sistem Avatar DIY (keputusan user)

Setiap staff/agent bisa kustom avatar sendiri — sistem slot-based ala game.

  • Satu base body rigged (CHAR_BASE) dengan skeleton sama untuk semua.
  • Part library per slot: rambut, wajah, atasan, bawahan, sepatu, aksesori.
  • Parts di-skin/parent ke bone CHAR_BASE → semua animasi berlaku untuk semua kombinasi. Parts tidak di-rig ulang.
  • Rigging dilakukan sekali untuk base body (Meshy Animate atau Mixamo).
  • Konfigurasi per staff disimpan di MongoDB, bukan di file 3D.
  • R3F merakit parts saat load berdasarkan config. UI pemilih avatar = fase berikutnya.
  • Semua parts wajib lulus §4.

7. Workflow

7.1 Scene Blender (gedung/interior)

  1. Baca §1–§6.
  2. Tulis/ubah fungsi builder di apps/assets/blender/build_hq.py (make_wall(), make_desk(), make_stairs(), …) — modular, linked duplicates.
  3. Jalankan via MCP execute_blender_code (atau headless blender -b -P build_hq.py).
  4. Save hq_vNN.blend (naikkan NN).
  5. Render Eevee (BLENDER_EEVEE) dua kamera: isometrik + eye-level → PNG.
  6. Baca PNG, jalankan checklist §4, revisi.
  7. (Opsional, Level 2 Kit Meshy) Import potongan kit dari apps/assets/raw/meshy/kit/ → normalisasi skala ke grid 1 m, pivot di dasar, Remesh (0 kredit) + rapikan tepi seam, ganti tekstur ke vertex color/palet §4.1 bila tidak lolos, nama KIT_<piece> → instancing oleh builder bpy. Collider tetap kotak bpy.
  8. Export GLB headless → gltf-transform (meshopt; KTX2 hanya jika ada tekstur).
  9. Verifikasi GLB: skala, orientasi, hierarchy, naming §6.
  10. Output kandidat → apps/web/public/models/hq.glb (ganti building.glb hanya setelah user setuju).

7.2 Karakter via API (tanpa buka web)

prompt (+ style §4, preferensi §5)
  → curl Meshy API (text/image-to-3D) → poll job → download GLB
  → import Blender via MCP → cek §4, rename sesuai §6
  → Meshy Animate API (rig + idle/walk/sit/type)  |  alternatif: Mixamo
  → export GLB animated → apps/web/public/models/
  • Alur API butuh Meshy Pro (free tier tidak punya API). Selama free tier: user generate di web Meshy, simpan GLB ke apps/assets/raw/meshy/, agent lanjut dari langkah import.
  • Langkah manual user hanya sekali: daftar akun + buat API key → .env (MESHY_API_KEY; SLOYD_API_KEY nanti bila Sloyd dipakai).
  • Addon mcp-for-blender punya integrasi built-in Tripo/Hyper3D (nonaktif, butuh key) — bukan pilihan utama.

7.3 Urutan fase

  • P0: deklarasi three/@react-three/fiber/@react-three/drei di apps/web/package.json → build_hq.py massing 4 lantai + Floor 1 detail (lobby, meeting kaca, 8 workstation, koridor, tangga) → 2–3 iterasi render → export & verifikasi GLB.
  • P1: helicopter/isometric camera → floor switching → room selection.
  • P2: FPV (WASD + mouse-look, pointer lock exit jelas) + collision COL_*.
  • P3: minimap → karakter Meshy + avatar DIY → integrasi agent backend.
  • P4: task board + Trello (§8).
  • Third-person view: opsional, paling akhir.
